## Toggle network proxies per machine

- [x] Define `dotconfig proxy on|off|status` semantics and an unmanaged, per-machine configuration source. Preserve proxy URLs, credentials, internal certificate paths, and an extensible `no-proxy.local` bypass list outside Git. `off` persists for new sessions and takes effect in the current managed Zsh shell.
- [x] Inventory network clients used by bootstrap, maintenance, and interactive development: curl, Git (including Oh My Zsh and Vim plugins), Homebrew, APT, mise, npm/CoC, and language installers or package managers such as pip and Go modules. Check which clients honor `HTTP_PROXY`, `HTTPS_PROXY`, `ALL_PROXY`, and `NO_PROXY`, including lowercase variants, and which need their own configuration. Recorded in [proxy-clients.md](proxy-clients.md); APT now gets exact-host `DIRECT` bypasses and Node.js gets `NODE_USE_ENV_PROXY=1`.
- [ ] Test the local Kerberos-aware proxies (cntlm-gss, proxy-detox, Px) when the listener or Kerberos ticket is missing, and confirm the rows marked *needs machine check* in [proxy-clients.md](proxy-clients.md).
- [x] Use a single loader for child processes and newly started shells. Cover `bash install.sh` before chezmoi has applied files, and preserve the selected mode when `dotconfig` launches Bash scripts. Avoid writing a public or machine-wide proxy URL into committed files.
- [ ] Verify Ubuntu APT under `sudo` on a real machine: dotconfig now creates `/etc/apt/apt.conf.d/10-proxy.conf` only when no APT proxy exists. Where existing APT proxy settings are absent, it passes proxy environment through `sudo --preserve-env`; local sudo policy may reject this. Keep existing system package manager settings intact.
- [ ] Test `on`, `off`, `status`, fresh bootstrap, a new shell, and package manager operations on macOS and Ubuntu; include `NO_PROXY` for corporate hosts.
- [x] Check that status, logs, plans, and error messages never print credentials. `scripts/test-proxy-secrets.sh` seeds fake credentials into the private files and fails if any output or persisted file repeats them.

The intended boundary is a machine-local network profile, not a proxy address shared across machines. A proxy switch should affect the tools launched through dotconfig and interactive shells consistently without rewriting users' unrelated package-manager configuration.

## Extend `dotconfig machine status`

Proposals from the review of PR #125: [general coverage](https://github.com/rmorozov/dotconfig/pull/125#issuecomment-6505930614), [desktop health](https://github.com/rmorozov/dotconfig/pull/125#issuecomment-6506002250) and [polkit](https://github.com/rmorozov/dotconfig/pull/125#issuecomment-6506081104). Each comment has acceptance scenarios; a task is done when its scenarios pass as fixtures, and as live CI or a disposable desktop where a fixture cannot prove it. Default inspection stays passive: no credential prompts, no D-Bus auto-activation, no resets, restarts or policy changes, and network probes only when asked for and bounded. Tasks marked *small* fit one short PR each.

- [x] Assessment completeness: `check failed` (a diagnostic that did not work) is kept apart from `not checked` (an expected limit), and the exit status separates problems (1), an incomplete assessment (3) and healthy within the checked scope (0). Delegated `dotconfig creds` checks are bounded and their failures propagate. Done in #125.
- [x] Inspect the right user and session (foundation for most tasks below): `--user NAME` for a local or domain account; UID, groups, home and XDG paths through NSS, not from the login name; session type, class, state, runtime directory, user manager and user bus; which observations are per user and which per session; logged-out or headless targets reported as unknown or not applicable. Compare only allowlisted environment variables and redact them.
- [x] Target-user installation health: ownership and effective access (ACLs included) of dotconfig-managed files, parent-directory traversal, broken symlinks, Zsh completion permissions, and root-owned generated files that block updates.
- [x] Proxy and TLS across execution contexts: configured proxy against the inspected session or process environment (stating which one), conflicting upper and lower case variables, unreachable local proxy listeners, missing or unreadable CA files. Optional bounded probes that tell DNS, connection, proxy negotiation and TLS failures apart, with verification kept on.
- [x] Expected services, timers and mounts from the machine role and enabled dotconfig features, with overrides: required units disabled, masked, inactive or skipped, overdue maintenance timers, and expected mounts missing while the mount point is writable.
- [x] *small* tmpfs exhaustion (`/run`, `/dev/shm`), user quotas, and detailed SMART and NVMe indicators where supported.
- [x] *small* Update and next-boot readiness: stale APT lists and failed refreshes, overdue unattended upgrades, DKMS modules not built for installed kernels, `/boot` capacity for the next kernel.
- [x] *small* CPU and I/O pressure next to memory PSI; per-service cgroup OOM and limit events; process and file-descriptor exhaustion. High utilization alone is not a fault.
- [x] Domain integration: NSS resolves the intended identity and home, domain discovery works through the current VPN and DNS, expected cached operation is told apart from unexpected loss of connectivity, and authentication, account authorization and session setup are separate stages.
- [x] GDM phases: display-manager unit and session definitions, greeter told apart from user sessions, authentication success followed by an immediate return to the greeter, Shell and greeter crash loops, missing session executables, user manager failures, home and runtime-directory access errors; password, smart-card, autologin and unlock paths separate; ambiguity reported when one user manager serves several sessions.
- [x] Keyring: owner of the Secret Service name in the target session, collection presence and lock state without reading secrets, unreadable storage, explicit unlock failures; passwordless logins leaving the keyring locked treated as expected; early startup warnings followed by recovery not reported as faults.
- [x] Indexing (Tracker or LocalSearch, discovered from the installed version): state, locations and exclusions, extractor crash loops and timeouts, database errors, unwritable cache, watch limits; pauses and deliberate disabling are not faults; "stuck" needs evidence over time; file names stay out of shareable output. Stuck is not judged from one run: a long busy spell is reported with a request to compare later.
- [x] polkit: authority and agent registration for the requesting session, administrator identities resolved through NSS (fully qualified domain names, offline domain), the polkit PAM path on its own, rule-loading errors and `.pkla` compatibility on the installed version, and outcomes kept as authorized, authentication required, denied, cancelled, check failed or unknown. Done passively: outcomes come from polkitd's log (authorized, authentication failed); denied, cancelled and authentication-required decisions are not logged, so they need an explicit probe.
- [x] Second-tier desktop checks: portal backend selection and activation failures, Shell extension errors after upgrades, dconf failures and policy locks, broken autostart entries, PipeWire and WirePlumber failures, and resume or unlock failures correlated with Shell and GPU errors.
- [ ] Reporting: each finding names the affected user, session or service, evidence time and scope, whether recovery was seen, and a next diagnostic command; historical incidents are separate from current failures, and inferred causes are labeled as hypotheses.
